# Lottery

**Статус:** готово
**Тип события в календаре:** Lottery

## 1. Где что настраивается

| Где | Что именно настраивается здесь |
|---|---|
| Инструмент (Lottery Simulator) | Баланс сундуков (4 предустановленных: Small/Medium/Big/Super + вариант Newbies), Item/Id/Дроп/Вес/Крафт по каждому предмету, сохранение/загрузка/переименование баланса |
| График ивентов (окно события типа Lottery) | Название → авто-Id (следующий свободный из Schedule), style, segment (из списка), start/end datetime, выбор сохранённого баланса, target (тест/прод) |

## 2. Google Sheets — точки записи

Всё оркеструется одним вызовом (`google:apply-lottery-partition`), который последовательно делает шаги ниже.

### Точка A: собственная таблица Lottery
**Прод-таблица:** 1d2mBr0-yDswgyFzTeaFHdbNEizukTEtCtaYkG3PzouI
**Тест-таблица:** 10s8UQTOfFupR3afkyU0nmvKo_crLPjREHFTolesQK54
*(тест/прод — это две ПОЛНОСТЬЮ разные таблицы, не разные листы в одной)*

**Паттерн:** дублирование шаблонных листов

- Если имя баланса заканчивается на `LotteryNewbies` → дублируются `NewbiesChest / NewbiesGameRewards / NewbiesInappsCurrency`. Иначе → `Chest / GameRewards / InappsCurrency`.
- Новые листы называются `<ИмяИвента>Chest`, `<ИмяИвента>Rewards`, `<ИмяИвента>Currency`.
- Новые листы вставляются сразу после листа `EggsAndPets` (если он есть).
- **Заполняется баланс только на первом из трёх листов** (Chest/NewbiesChest). Rewards и Currency дублируются как шаблон и **не редактируются инструментом вообще** — это осознанное разделение, не баг, правятся вручную.

**Поля строки на листе Chest** (10 колонок, ищутся по заголовку, порядок в таблице не важен):
`container_id, container_type, category, item_type, item_id, alternative_reward, ShowInPreview, item_subtype, count, drop_chance`

**Структура строк — блоками по 100:**
- Блок = `Math.floor(containerId / 100) * 100` (Small = 100-е, Medium = 200-е, Big = 300-е, Super = 400-е).
- Если в симуляторе для блока айтемов больше, чем строк на листе — строки вставляются (с копированием формулы из колонки `drop_chance (400)%`, если она есть).
- Если меньше — лишние строки удаляются.
- Блок, которого вообще нет на листе — ошибка, авто-создание нового блока не поддерживается.
- Повторяющиеся `container_id` внутри симулятора — ошибка до записи.

**Лист Schedule** — добавляется новая строка (копия последней строки с подменой полей, не создание с нуля):
- Поля, которые реально подставляются: **имя** (колонка A), **style** (колонка B), **uniqueId = Id** (колонка H)
- Остальные колонки наследуются от предыдущей строки как есть

**Вспомогательно (для UI, не запись):**
- Следующий свободный Id — максимум колонки `UniqueId` на Schedule + 1 (fallback, если лист пуст: 2163)

## 4. Ограничения

- Точное совпадение имени листа при сборке конфига (пробелы и регистр).
- Проверка повторяющихся ID и наличия всех container_id перед батч-записью; при ошибке структуры — без частичного изменения таблицы (но обновление значений и структурные insert/delete строк идут отдельными запросами, см. открытые вопросы).
- Нулевая стоимость открытия (Super Chest) — валидна, не менять на 1/5.
- Big Chest значения (см. `bigChestItems` в `src/LotterySimulator.jsx`) — не менять без отдельного требования.

## 5. Известные особенности (подтверждены, не баги)

- Два последовательных API-запроса (структура, потом значения) без транзакционности между ними — принято как есть, не чиним.
- Rewards и Currency никогда не редактируются инструментом — это намеренно, всегда правятся вручную.
