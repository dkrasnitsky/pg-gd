# EventCenterConfig ↔ График ивентов

**Статус:** готово. Односторонняя синхронизация «конфиг → график» (новые события) + двусторонняя синхронизация статуса `IsEnable`.

## 1. Назначение

Пока не все ивенты заводятся через График (часть команды всё ещё конфижит напрямую в EventCenterConfigV2) — кнопка «Синхронизировать с EventCenterConfig» в шапке Графика ивентов подтягивает то, что уже сконфижено в таблице, без ручного переноса.

## 3. Важная находка — числовой формат дат

Часть строк (замечено на листе PixelPass) хранит `StartDate`/`EndDate` как **настоящую дату Google Sheets**, а не текст — `valueRenderOption=UNFORMATTED_VALUE` в этом случае отдаёт число (сериал даты, дни с 30.12.1899), а не строку `"2026-09-01T10:00:00"`. Если это не учесть — дата либо теряется (`end` подставляется равным `start`), либо строка целиком пропадает из результата.

Решение — `normalizeSheetDate()` в `readEventCenterTab` понимает оба формата:
- строку `YYYY-MM-DD...` — как есть;
- число — конвертирует через `Date.UTC(1899,11,30) + value*86400000`.

Если где-то ещё встретится этот же тип ошибки (значение "теряется" при чтении) — с высокой вероятностью там та же причина.

## 4. Группировка и дедупликация

- Строки с одинаковым `type + Style + StartDate + EndDate` объединяются в одно событие графика (актуально для Personal Event/Template Event, где один ивент заводится по нескольку раз на разные сегменты).
- Каждое созданное синком событие календаря помечается скрытыми полями: `sourceEventIds` (список EventId из конфига), `sourceStyle`, `sourceSegments`.
- При повторном синке эти id используются, чтобы не создавать дубликаты — событие считается «уже известным», если хотя бы один из его `sourceEventIds` совпадает с id строки из конфига (с тем же типом).
- Глубина истории — только с начала текущего года (`new Date(currentYear,0,1)`).

## 5. Статус IsEnable — двусторонняя синхронизация

- **Из графика в конфиг:** в карточке события (по клику) есть чекбокс «Включено». Меняя его, приложение находит нужный лист по типу события и пишет `true`/`false` в колонку `IsEnable` для всех `sourceEventIds` этого события (`google:set-event-enabled`). Если у события нет `sourceEventIds` (создано вручную, не через синк) — статус чисто локальный, в таблицу ничего не уходит (в интерфейсе есть пометка об этом).
- **Из конфига в график:** при повторном нажатии «Синхронизировать» модалка теперь показывает **два списка**: новые события (как раньше) и **изменения статуса** у уже добавленных событий, если реальный `IsEnable` в таблице разошёлся с тем, что сохранено в графике. Каждое можно принять или снять галочку по отдельности.
- `IsEnable` пишется как настоящий boolean (`true`/`false`), не строка — иначе Google Sheets ругается на валидацию чекбокса (тот же урок, что был на Schedule у Personal Event).

## 6. Визуализация статуса на графике

- Включено (по умолчанию, `enabled !== false`): сплошная заливка цветом типа, тёмный текст.
- Выключено (`enabled === false`): фон = фон графика, рамка и текст — акцентный цвет типа события (не сплошная заливка).

## 7. Разметка графика (сопутствующие правки в этом же заходе)

- События сортируются сверху вниз по фиксированному порядку типов: Pixel Pass → Template Event → Lottery → Card Roulette → Personal Event → Ads Roulette (→ Core Event и прочие — в конце).
- Внутри своего типа дорожки пересчитываются заново под текущий видимый месяц (жадная упаковка непересекающихся событий), а не растут бесконечно вниз, как раньше (было: у каждого события фиксированный `lane`, сохранённый навсегда).
- Высота ряда/блока события уменьшена ~в 1.5 раза (ROW_HEIGHT 52→35, высота блока 40→27) — больше событий помещается на экран.
- Название события теперь в приоритете над бейджем типа: бейдж скрывается целиком (через CSS container query), если сам блок уже 160px, вместо того чтобы оба текста конкурировали за место.
- Ручное перетаскивание по вертикали (смена дорожки) убрано — раскладка теперь полностью автоматическая.

## 8. Открытые вопросы / отложено

- Дедупликация и статус учитываются только для типов, у которых есть соответствующий `gidMap` (все 6 текущих). Если появится новый тип события в EventCenterConfig — нужно будет добавить его сюда и в `google:sync-event-center`/`google:set-event-enabled`.
- Изменение дат/сегмента у уже известного события синком пока не отслеживается — только статус `IsEnable`. Если понадобится — расширить `statusChanges`-механизм по аналогии.

## 9. Подтверждённый (реальный) id в карточке события

У события (Lottery/Card Roulette/Personal Event) есть разница между «предложенный id» (превью при открытии несозданного евента или партиции) и «реальный id» (то, что реально ушло в таблицу после успешного «Создать конфиг»). До этого исправления оба вида показывались одинаково — при повторном открытии настроек всегда перетягивался «следующий свободный id», даже если событие уже реально существовало в таблице.

**Фикс:** добавлен флаг `committed` — у Lottery/Card Roulette на каждой партиции (ставится в `true` только после успешного apply), у Personal Event — один общий флаг на `personalEventConfig` (связан с конкретным `subtype`, так что смена подтипа сбрасывает подтверждение). Пока `committed=false` — конфигуратор свободно тянет «следующий id» с сервера; после `committed=true` — показывает реальный id из сохранённого `lastResult`, поле id становится только для чтения.

Важно: обычное «Ок» (без нажатия «Создать конфиг») у Personal Event раньше стирало `committed`/`lastResult` при сохранении черновика (потому что `update()` заменяет весь `personalEventConfig` целиком, а не сливает) — теперь `saveDraft` явно пробрасывает их вперёд, если подтип не менялся.

В основной карточке события («EVENT DATA») теперь сразу видна строка `Id: ...` — считается через `resolveEventRealId()` (для Lottery/CardRoulette — список `committed`-ид партиций, для Personal Event — `lastResult.eventId` при `committed`, для всего остального — `sourceEventIds`), без необходимости открывать конфигуратор.

## 10. Ещё три фикса (Card Roulette Schedule + дедупликация + дефолтное время)

- **Lottery/CardRoulette Schedule и EventCenterConfig копировали `IsEnable` с последней строки** вместо явного `false` для нового события — если последняя строка была включена, новая тоже создавалась включённой. Исправлено в общих функциях `appendLotteryRow` (EventCenterConfig, используется и Lottery, и CardRoulette) и `appendCardRouletteScheduleRow` (собственный Schedule Card Roulette) — обе теперь явно пишут `false`.
- **В Schedule Card Roulette писалось имя листа** (`Chests_BlablablaSet`) вместо `Style` (`blablabla_set`). Исправлено — теперь пишется `style`, а не `names.chests`.
- **Дубли при повторной синхронизации:** события, созданные вручную через Lottery/CardRoulette/PersonalEvent конфигураторы (не через синк из EventCenterConfig), не получали `sourceEventIds` — при следующей «Синхронизации с EventCenterConfig» они распознавались как «новые» и добавлялись повторно. Исправлено — при успешном `apply()` каждый конфигуратор теперь также прописывает `sourceEventIds` на верхнем уровне события (для Lottery/CardRoulette — список `committed`-id партиций; для Personal Event — `[lastResult.eventId]`).
- Время по умолчанию для новых событий календаря — `09:00`/`09:00` (было `10:00`/`18:00`).
