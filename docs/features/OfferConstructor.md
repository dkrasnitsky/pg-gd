## 2. Экран 1 — список офферов

- Поиск по названию (`Label`, либо `GameOfferGui.TextTitle`, либо `Оффер <Id>` если нет ни того ни другого).
- «Всякие фильтры» — заглушка, не реализовано.
- «Синхронизация» — читает GameOffer + GameOfferGui + PriceTier целиком, склеивает по `GameOfferGui`/`GameOfferGuiDouble`, кладёт в локальный кэш (`gameOffersCache`), который используют и Календарь (для кампаний), и сам инструмент.
- Список — flex-раскладка на всю высоту окна (без второго скролла страницы), кнопки «В начало»/«В конец» прокручивают список.
- «Копировать» **не пишет в таблицу сразу** — просто запоминает оффер локально. В редакторе появляется кнопка «Вставить скопированное», которая заполняет форму (с пустым Id — создаст новую строку при сохранении).
- «Удалить» удаляет строку из GameOffer (GameOfferGui не трогает — она может использоваться другими офферами).

## 3. Экран 2 — редактор оффера

- Все поля GameOffer + GameOfferGui, кроме `ColorLabel1/2`/`TextLabel1/2` (не нужны по решению Димы).
- Поля-списки (Type, PriceTier, Country, GameOfferGroup, PlatformList, Expression, и все Prefab/Image/Bank-поля Gui) — собственный компонент с выпадающим списком (не браузерный `datalist` — были проблемы с подсветкой автозаполнения, невозможностью переоткрыть список и отсутствием скролла у длинных списков). Список значений — **уникальные значения, реально встречающиеся в колонке** на момент последней синхронизации, плюс всегда можно вписать своё.
- `Price` — только отображение, авто по `PriceTier` из справочника, не редактируется напрямую.
- `Expression` — два поля: выбор готового варианта (список существующих Expression) и сам текст, который реально уходит в таблицу; выбор из списка просто подставляет текст в поле, можно поправить.
- `GameOfferGui`/`GameOfferGuiDouble` — кнопка «+»: выключена → редактирование существующей строки (правки затронут всех офферов, которые её используют — предупреждение показывается прямо в форме); включена → при сохранении создаётся новая строка Gui с новым id.
- Новый Gui по умолчанию получает `TextTimeLeft=Key_11451, TextPrice=Key_14484, TextOldPrice=Key_11453, TextButtonBuy=Key_14484, TextSale=Key_11455` (это ключи локализации, не текст — можно поправить).
- `PreviewOldPrice` — чисто локальный расчёт для дизайнера: `Price / (1 - SaleAmount/100)`. Считается от настоящей цены оффера (`$`), а не от `TextPrice` (который является ключом локализации, а не числом — это была реальная ошибка в первой версии, исправлена).
- Новые id: GameOffer — `<число>211`, GameOfferGui — `<число>213` (число = максимум существующих +1). Найдено эмпирически по реальным данным, не подтверждено официально Димой как жёсткое правило — если где-то создастся id не по этой схеме, стоит перепроверить.

## 4. Экран 3 — кампания в Графике ивентов

- Новый тип события «Offers» — по требованию всегда внизу списка типов на графике (`TYPE_ORDER`).
- Кампания = название (только для графика, никуда не пишется) + даты + список офферов (по ссылке на id, из локального кэша `gameOffersCache`).
- «Создать конфиг»: офферам без собственных дат — даты кампании проставляются автоматически. Офферам, у которых уже есть даты — отдельный шаг с чекбоксами (по умолчанию не отмечены), только явно отмеченные перезаписываются.
- `IsEnable` для кампании (чекбокс в карточке события) пишет сразу во все офферы кампании — отдельная ветка в `google:set-event-enabled` (таблица другая — GameOffersSystem, а не EventCenterConfig).

## 5. Кросс-навигация между вкладками

- Offer Constructor → «В график ивентов»: открывает вкладку Календаря, создаёт черновик кампании с этим оффером, сразу открывает конфигуратор кампании (через `pendingCampaignOffer` в App.jsx).
- Календарь (кампания) → «В конструктор» на конкретном оффере: открывает вкладку Offer Constructor и сразу его редактор (через `pendingOfferId` в App.jsx).
- Оба механизма используют `{id/offerId, nonce}` с nonce-меткой времени, чтобы срабатывать даже при повторном клике на один и тот же оффер, пока вкладка уже открыта.

## 5б. Кнопка «Тест» в конфигураторе кампании

**Тестовая таблица:** 1doZu0uLJTyNiAlx1D3SHih4Lw6AJDvVNpxMMvx6pjLE (предполагается, что это копия прод-таблицы — используются те же gid листов GameOffer/GameOfferGui, что и в проде — не подтверждено напрямую, если ошибка «Лист не найден» — значит gid там другие).

**Принцип:** из тестовой таблицы **ничего не читается**. Берётся полный объект оффера из локального прод-кэша (`gameOffersCache`, включая Gui/GuiDouble), и пишется в тестовую таблицу **теми же id**, что в проде (не генерируется новый). Колонки матчатся по названию (не по позиции) — если тестовая таблица немного отличается по порядку столбцов от прода — не страшно.

- Если строка с таким id уже есть в тесте — обновляется; если нет — добавляется новая строка (`upsertByExactId`, отдельная функция от прод-версии — та генерирует новый id, эта — никогда).
- Gui/GuiDouble копируются так же, своим id.
- Даты кампании всегда проставляются всем выбранным офферам без вопроса про конфликты (в отличие от прод-кнопки «Создать конфиг») — логично, раз мы ничего из теста не читаем и не знаем про существующие там даты.
- Календарное событие кампании при этом НЕ создаётся/обновляется — кнопка «Тест» только пишет в таблицу, ничего не меняет в локальном Графике.

## 6. Сопутствующая правка календаря

- `.calendar-days` (шапка с датами) теперь `position: sticky; top: 0` — при скролле вниз (актуально из-за офферов, которые всегда внизу списка типов) шапка с датами не уезжает.
